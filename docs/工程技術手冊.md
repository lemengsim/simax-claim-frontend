## 二、API 端點規格

### GCP Express Server（port 3001）

#### `GET /health`
健康檢查，無需認證。
```json
{ "status": "ok", "ts": "2026-05-15T00:00:00.000Z" }
```

#### `POST /api/internal/verify`
訂單驗證，回傳數量。

Request:
```json
{
  "orderNo": "26051417231696",
  "email": "user@example.com",
  "internalKey": "<INTERNAL_API_KEY>"
}
```

Response (成功):
```json
{ "valid": true, "qty": 2, "goodsName": "日本 吃到飽 1天" }
```

Response (失敗):
```json
{ "valid": false, "message": "查無此訂單或尚未完成出貨" }
```

#### `POST /api/internal/redeem`
電子票券核銷 + 廠商叫貨 + 回傳 QR Code。

Request:
```json
{
  "orderNo": "26051417231696",
  "email": "user@example.com",
  "ticketPins": ["AB1234567890", "CD9876543210"],
  "internalKey": "<INTERNAL_API_KEY>"
}
```

Response (成功，多件):
```json
{
  "success": true,
  "items": [
    {
      "order_id": "26051417231696-item1",
      "product_name": "日本 吃到飽 1天",
      "vendor": "DJB",
      "qr_code_data": "LPA:1$rsp.esimcase.com$C6NLQ-55BU0-35I1K-IC0LI",
      "iccid": "89886930000123456789"
    }
  ],
  "message": null
}
```

Response (DJB QR PENDING):
```json
{
  "success": true,
  "items": [
    {
      "order_id": "26051417231696-item1",
      "qr_code_data": "DJB_PENDING:12345678",
      ...
    }
  ],
  "message": "eSIM 建立中，QR Code 將於 5-15 分鐘內備妥，請稍候再試"
}
```

#### `POST /api/verify`

```
    "company_fr_hh": "00",
    "company_fr_mm": "00",
    "company_to_dd": "YYYY/MM/DD",
    "company_to_hh": "23",
    "company_to_mm": "59",
    ...
  }
}
```

Response:
```json
{ "rtnCode": "0000", "rtnMsg": "success", "dataList": "<AES-128-ECB加密字串>" }
```

### AES-128-ECB 解密流程

```
金鑰 = MOMO_ENTP_PWD.padEnd(16, '0').substring(0, 16)
解密 = AES-128-ECB PKCS5Padding，input: Base64字串，output: JSON陣列字串
```

Node.js 實作（momo-ingest.js）:
```javascript
const aesKey = rawPassword.padEnd(16, '0').substring(0, 16);
const decipher = crypto.createDecipheriv('aes-128-ecb', Buffer.from(aesKey), '');
let decrypted = decipher.update(encryptedBase64, 'base64', 'utf8');
decrypted += decipher.final('utf8');
return JSON.parse(decrypted);
```

## 五、DJB API 技術規格

### Checksum 計算

```
raw    = DJB_API_IV + YYYYMMDD(台灣時區) + source_number
b64    = Base64(raw)
checksum = MD5(b64).toLowerCase()

source_number 格式 = "simax" + YY + MM + DD + HH + mm + ss + 3碼亂數 + "1"
```

### 下單 (application/x-www-form-urlencoded)

```
POST https://api.djbsim.com/api/order/buy
key, date, checksum, source_number, product_code, days, quantity, name, email
```

### 查詢 QR

```
POST https://api.djbsim.com/api/order/info
key, date, checksum, source_number, channel_sub_order_id
```

Response 取 qrcode_content（多層路徑任一有值即可）:
```javascript
result?.data?.qrcode_content
result?.data?.data?.qrcode_content
result?.data?.cards?.[0]?.qrcode_content
result?.qrcode_content
```

## 七、大腦比對演算法

四層防護（core-mapper.js）：

```
1. 字首30字：只取商品名稱前30字元比對（避免尾巴冗餘干擾）
2. AND比對：Plans A欄逗號分隔關鍵字，每個都必須命中才算匹配
3. 正則邊界：避免「日」誤匹配「日本」
   regex = /(?:^|[\s,，、()（）【】／/天日%GB－-])<keyword>/i
4. 加權計分：score = Σ(keyword.length × 2 + 1) + keywords.count × 3
             取最高分者
```

字典快取：30分鐘 TTL，重啟或快取過期時從 Google Sheets 公開 CSV 重新載入。

## 八、常見問題與除錯

### Q: PM2 simax-engine 掛掉

```bash
pm2 status                    # 查看狀態
pm2 logs simax-engine --lines 50  # 看最後50行 log
pm2 restart simax-engine      # 重啟
```

### Q: 字典比對失敗（無法比對廠商代碼）

1. 確認 Plans 分頁 A 欄關鍵字格式正確（逗號分隔，例：`日本,吃到飽,1天`）
2. 確認 Plans 分頁設定為「知道連結者可檢視」
3. 等待30分鐘快取過期，或重啟 simax-engine 強制重載

### Q: DJB QR Code 一直 PENDING

1. 查 PM2 log 確認 djbOrderId
2. 手動打 DJB `/api/order/info` 查狀態
3. activation-poller.js 未啟動時，需手動補回 QR（或重啟引擎讓顧客重新領取）

### Q: Google Sheets 寫入失敗

- 不影響顧客領取 QR Code（主流程已完成）
- 確認 VM service account 有 Sheets 編輯者權限
- 確認 ADC 設定正常（GCE 上自動套用 VM service account）

### Q: Vercel 前台無法連 GCP

1. 確認 Vercel 環境變數 `GCP_REDEEM_URL` 是否為正確 IP
2. 確認 GCP VM 防火牆允許 port 3001 入站
3. 確認 `pm2 status` simax-engine 是 online 狀態
4. 用 `curl http://<GCP_IP>:3001/health` 驗證連通

### Q: 訂單已領取但無 ICCID 顯示

- ICCID 僅在「此功能上線後」發貨的訂單才有值
- 舊訂單 Supabase orders.iccid 為 null，前台不會顯示（正常行為）
- 若新訂單也沒有 ICCID，確認 DJB API response 是否包含 iccid 欄位

## 九、git 操作注意事項

### index.lock 問題

VM 和沙箱環境無法刪除 Windows 掛載目錄的 lock 檔，每次 push 前在 PowerShell 執行：

```powershell
Remove-Item "C:\Users\yume\Desktop\SIMAX 整合系統\simax-clone\.git\index.lock" -Force
```

### Commit 標準格式

```
v<版本號> | YYYY-MM-DD | 簡述改了什麼
```

範例：`v2.12.0 | 2026-05-15 | Step 2 文案微調；按鈕間距調整`

### VM 程式碼更新流程

VM 上的程式碼無法直接用 git push 更新，需：
1. 修改本地檔案確認無誤
2. 用 `scp` 或 `gcloud compute scp` 傳到 VM，或
3. SSH 進 VM 用 `sed`/`vim` 直接 patch
4. `pm2 restart simax-engine` 生效

## 十、重要決策記錄

| 決策 | 原因 | 排除的方案 |
|------|------|-----------|
| 不使用 CryptoJS，改用 Node.js crypto | GCP VM 原生支援，不需額外安裝 | CryptoJS npm |
| Plans 分頁公開CSV讀取 | 不需複雜OAuth設定 | googleapis + service account |
| DJB 用 form-urlencoded，WM 用 JSON | 依各廠商 API 規格 | 統一格式 |
| PENDING 狀態存入 Supabase | 顧客重新領取時可查歷史，不重複叫貨 | 直接回錯誤 |
| 前台 ticketPin 12碼英數字 | MOMO 電子票券序號格式，regex: /^[A-Z0-9]{12}$/i | 不驗格式 |
